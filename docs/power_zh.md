# 功耗参考值与指标来源

[English](power.md) · [README](../README_zh.md)

## 如何理解功耗显示

`Pwr:Usage/Ref` 表示**实时功耗 / 额定参考值**，单位为 W。主表取整显示，
详情页与 JSON 保留原始精度。nputop 当前不提供经过验证的驱动强制功率上限。

多芯片卡在首个可见芯片显示一组数值，例如 `170W / 949W`；其余行显示
`↳ Card 0`，各芯片的温度、内存和利用率仍独立显示。实时功耗选用该卡已枚举
芯片中最新的有效读数；全部过期时显示最新保留值并标 `*`；没有读数时显示
`NA`。时间戳相同则取芯片编号最小的一条。

这是一条接口代表读数。对于测量范围可能重叠的读数，nputop 不求和、不平均、
不除二，也不据此推导整机功耗。筛选显示设备不会改变读数来源；详情保留每个
芯片的原值、状态及选用来源。

虽然表中不加 `~`，`Ref` 仍表示估算参考值。同卡共享参考值冲突时显示 `NA`。
展开模式的 PWR 条使用未取整的实时值与参考值计算比值，百分比末尾标注 `ref`；
它不是已验证强制功率上限的百分比。

## 来源与回退顺序

1. **实时功耗：**DCMI 芯片接口按 `原始值 × 0.1 W` 换算，SMI 保留瓦特值。
   缺失时保持 `NA`，不把型号参考值或相邻 die 的读数填入原始指标。
2. **额定参考值：**初始化时探测可选接口 `dcmi_get_device_info`，通过
   `LP(8) / GET_POWER_INFO(10)` 读取 36 字节结构中的 `soc_rated_power`。
   对识别出的 910 系列，**推测单位为 mW**，以 `原始值 / 1000` 换算为 W。
   单位与额定范围仍为推测，不是已验证的功率上限契约。查询失败、长度错误、
   零值或无效哨兵值、不支持的系列、不合理数值均放弃该读数。来源、原值、
   返回码、长度及推测依据保留在元数据中。
3. **型号表回退：**额定数据不可用时，按精确型号使用以下历史估算值；
   未知型号保持未知。

| 型号 | 参考值 |
| --- | --- |
| 310P1 | 90 W |
| 310P3 | 72 W |
| 910A | 310 W |
| 910B | 265 W |
| 910B1 | 430 W |
| 910B2 | 420 W |
| 910B3 | 350 W |

这些是估算值，不是实测上限。核心数和频率不能单独涵盖电压、内存、互联与板级
损耗，nputop 不按这些参数动态线性推算功耗。

新界面不采用范围不明的历史 `910C = 350 W`。为保留旧 API 兼容性，
`Device.power_limit()` 的查表行为与 W 单位保持不变，`power_usage()` 仍为 mW。
原生快照的 `metrics.power` 仍为 W；`power_reference` 是独立元数据，
不会冒充实测上限。

## 910C 拓扑与推测边界

华为作者的 [CloudMatrix384 论文 §3.3.1](https://arxiv.org/html/2506.12708v2#S3.SS3.SSS1)
说明每颗 910C 有两个计算 die，每 die 有 24 个 AIC 核心和 64 GB 内存。
这里指计算 die，不代表封装内所有物理 die；DCMI DIE 标识数组的五个元素
也不代表五个计算 die。nputop 使用驱动枚举，不按型号写死芯片数量。

相邻 die 的功耗读数相近或略有差异，都不能单独证明测量范围。
[Ascend-DMI 文档](https://www.hiascend.com/document/detail/zh/mindcluster/71RC1/toolbox/toolboxug/toolboxug_0019.html)
说明 A3 工具采用整卡口径，但不能证明每种固件的每个 DCMI 读数均代表整卡。
因此实时值不缩放，测量范围仍标记为待核实。

另对**额定参考值推测整卡共享范围**：仅在型号明确为 `910C`，或板型 ID 为
`0xb0`–`0xb4` 时采用。板型依据来自
[Ascend MindCluster 的 A3 常量](https://github.com/Ascend/mind-cluster/blob/3779de1d5dd633929d21066767a6c9efedbeb937/component/ascend-common/devmanager/common/constants.go)。
只有通用名称 `Ascend910`、产品码 `9382` 或两个芯片，均不足以判定。

例如 A3 接口返回额定原始值 `949200` 时，得到 **949.2 W 的推测整卡参考值**，
主表只显示一次 `949W`。它不是每 die 的上限，也不是已验证的强制功率上限；
该数字来自接口，并未写死在代码中。
[A3 额定查询文档](https://www.hiascend.com/doc_center/source/zh/HDK/2610/A3/A3DCMI/dcmia3_078.html)
给出字段名和 150000–600000 的范围，但没有明确单位。由于实测 A3 原值超出
这一范围，nputop 对识别出的 A3 使用 150000–2000000 的推测性合理范围检查，
其他已识别 910 设备仍采用 150000–600000。这些是异常值防护范围，不是硬件规格。

分组依据完整快照中的卡／芯片编号，不依赖显示编号相邻，也不假设固定两个芯片。
只显示部分成员时，完整模式标注如 `1/2 dies`，紧凑模式用 `2c` 表示两个
已枚举芯片。驱动只暴露一个 A3 芯片时，参考值仍标为 `card`，不猜测隐藏读数。
通用设备标为 `chips`。显示分组不能证明共享传感器，普通逐芯片参考值也不会
被提升为整卡参考值。

[SemiAnalysis 的 CloudMatrix384 分析](https://semianalysis.com/2025/04/16/huawei-ai-cloudmatrix-384-chinas-answer-to-nvidia-gb200-nvl72/)
等系统级资料可提供背景，但无法证明某个固件字段的单位或单 die 上限。
后续实机证据可能修订这些推测。

## 310P 指标处理

芯片功耗不支持时，探测可选的 `dcmi_mcu_get_power_info(card_id, &power)`
整卡功耗接口。0.1 W 单位依据
[昇腾官方 MCU 封装](https://github.com/Ascend/mind-cluster/blob/3779de1d5dd633929d21066767a6c9efedbeb937/component/ascend-common/devmanager/dcmi/dcmi.go)。
详情标明整卡范围。查询也不可用时显示 `NA`，72 W 的型号参考值不会替代
实时功耗。显式 SMI 模式只使用 SMI 输出。

310P 整体利用率不支持时，**UTL\*** 显示 AICore，包括真实 0%，历史图和详情
标明来源。原始 JSON 的 `npu_overall` 保留不可用状态；其他型号及临时错误
不使用此回退。该约定不代表 AICore 与 NVML 利用率定义相同。

## 展开模式的 MBW 与 PWR

完整模式在终端至少 140 列时，将 MBW/PWR 与 MEM/UTL 并排显示；100–139 列
保留 MEM/UTL，更窄时保留数字设备表。紧凑模式在 124 列起并排显示 MEM/UTL，
100–123 列只显示 MEM。高度不足时先压缩布局，再允许滚动，完整设备清单仍可访问。

MBW 表示**内存带宽利用率百分比**，不是内存容量占用率，也不是 GB/s。采集器
复用 HBM 查询中的带宽和时钟；不可用时探测 HBM 利用率类型 10 与频率类型 6。
HBM 能力不支持时才尝试 DDR 类型 5 与频率类型 1；权限不足或临时错误不会触发
其他计数器替代。内存时钟单位为 MHz。这些计数器不保证与 NVML 的采样定义一致。

[华为 A3 利用率文档](https://www.hiascend.com/doc_center/source/zh/HDK/2610/A3/A3DCMI/dcmia3_055.html)
指出直通虚拟机的带宽零值可能无实际意义。检测到虚拟机标记时，HBM 零值标为
不可用并解释原因，原始零值保留在元数据中。检测仅尽力而为，容器不自动视为
虚拟机。其他真实零值正常显示，缺失 MBW/PWR 显示 `NA`，过期值保留 `*`。
显式 SMI 未报告的字段保持不可用，芯片指标不会替代缺失的进程级指标。
